## 尚未关闭：F02 合成按钮内部品质文字仍被重建

**优先级：P2。位置：game/index.html:1160。**

外层 button 和标题 span 已常驻，但每次 renderPanels 仍通过标题的 innerHTML 重建“报废”“破损”等品质子 span。因此按不同位置会出现不同结果：

| 起触位置 | 不发生掉落，跨刷新 | 按住期间实际 dropRoll(true) 掉落 |
|---|---|---|
| button 自身 | 通过 | 通过 |
| 外层标题 span | 通过 | 通过 |
| 品质文字子 span | 失效、tapBtn 残留 | 失效、tapBtn 残留 |

补充短点验证：2× 下按住“报废”100ms，位移 9px，并将测试刷新计时对齐到该短点内。原品质节点脱离文档，合成事件增量为 0，tapBtn 残留。

通过 elementFromPoint 检查，品质文字确实可以成为实际命中元素；不是只在脚本里构造了用户无法命中的节点。

**与上版的区别：** 上版在装备内容变化时才重建；当前品质文字即使内容不变也每次刷新重建。因此外层修复有效，但内部文字的点按仍未可靠。

### 建议收尾

1. 品质文字节点也只创建一次，后续仅更新其 class 和 textContent，停止对整个标题设置 innerHTML。
2. 不要仅缓存整段文本；品质变化恰好发生在按住期间时，仍须保留目标节点。
3. 补充目标确需删除或隐藏时的手势清理，避免 tapBtn 残留影响后续操作。
4. 回归覆盖按钮空白、图标、普通标题、输入品质、产出品质，并分别叠加定时刷新、掉落和换装。
