## 问题详情与复现

### F01 · P1 · 每次读档都将装备品质再提高两档

- **复现**：获得装备后刷新页面，记录品质，再次刷新。
- **实际结果**：浏览器实际观测：武器 q0→q2→q4，装甲/芯片 q2→q4→q6；反复读取最终到 q9。
- **预期**：当前版本存档再次读取时，品质与属性保持不变；旧版本迁移只执行一次。
- **原因定位**：load() 无条件执行 it.q+2，存档没有迁移版本标记。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:531)。
- **修复建议**：增加存档 schema/version 并保证迁移幂等；新档显式写版本。未标记的历史存档可能已是新版数据，不能继续盲目整体 +2，需明确兼容策略。
- **证据用例**：C28, B03。

### F02 · P1 · 击杀与死亡同帧会出现“受阻但仍推进且不扣血”

- **复现**：在可控测试中让 Boss 剩 1 血、护盾为 0、玩家极低血量，并使下一次攻击当帧触发。等待击杀转场完成。
- **实际结果**：浏览器观测：第 2 层、玩家 HP=100、wall=true、paused=false，受阻弹窗仍显示，敌人 HP 已被打到17.65；后续敌人伤害被 wall 判断跳过。
- **预期**：同一帧战斗结果只结算一次；已死亡敌人不反击；受阻状态不得被转场异步回调恢复战斗。
- **原因定位**：dealPlayerHit() 内 onKill() 已推进楼层，主循环仍继续结算旧敌人伤害；随后转场回调无条件 paused=false，wall 却没有被清除。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:1173)。
- **修复建议**：把击杀/死亡收敛为互斥结算；攻击后若目标已死或状态已改变则退出本帧伤害流程；转场回调在受阻时不得恢复战斗。截图：12-kill-death-race.png。
- **证据用例**：C12, C48, B12。

### F03 · P2 · Boss 死亡动画期间复位会泄漏旧技能弹窗

- **复现**：第 5 层 Boss 击杀后、约 0.9 秒死亡等待尚未结束时，点击复位并确认。
- **实际结果**：用实际复位按钮复现：新开局第 1 层仍出现第 5 层的触发器三选一，pendingOffer 被旧回调重新写入，游戏暂停。
- **预期**：复位作废上一局全部异步任务，新开局无技能候选。
- **原因定位**：普通怪和部分跑入回调检查 runSeq，Boss 死亡后的回调缺少这一检查。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:703)。
- **修复建议**：为 Boss 延迟回调加入统一代次校验；复位清理 skillOfferOpen、curOffer、pendingTransit 等流程状态。截图：14-reset-stale-skill.png。
- **证据用例**：C15, B23。

### F04 · P2 · 继续存档时楼层文字与战斗背景不一致

- **复现**：保存第 10 层进度，刷新并点击进入夜城，等待双方跑入完成。
- **实际结果**：楼层文字为“第10层／棱镜核心”，实际 backgroundImage 为 arena-bg.webp；应为 arena-bg4.webp。
- **预期**：新开局、重塑和读档的背景与当前楼层调度一致。
- **原因定位**：openingRunIn() 更新楼层显示，但未按 bgForFloor(S.floor) 初始化 arena 背景；背景只在 sceneSwap() 时更新。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:743)。
- **修复建议**：所有开局入口统一初始化当前场景，再开始跑入。截图：07-reload-background-mismatch.png。
- **证据用例**：B05。

### F05 · P2 · 每层第一只怪交战中刷新可恢复满血

- **复现**：任意层第一只怪（mobIdx=0）交战时保存 33/100 HP，再刷新。
- **实际结果**：实际浏览器读档后 HP 从33恢复到100；其他 mobIdx 的存档血量恢复正常。
- **预期**：恢复已进行中的战斗应使用存档血量；只有真正进入新层才回满。
- **原因定位**：spawnMob() 用 mobIdx===0 同时代表新层和第一只怪的读档恢复。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:625)。
- **修复建议**：区分新层初始化和存档恢复，恢复流程优先使用已保存的血量。
- **证据用例**：C31, B22。

### F06 · P2 · 存储写入异常会中断战斗主循环

- **复现**：故障注入：使 Storage.setItem 抛出 QuotaExceededError，等待周期保存。
- **实际结果**：浏览器实际观测最后一帧时间停止更新，距当前时间已5981ms；恢复存储方法后仍需重新加载才能恢复循环。
- **预期**：保存失败给出提示或进入可恢复状态，不应让游戏静默冻结。
- **原因定位**：save()/saveLogs() 未隔离存储异常；异常打断 loop()，末尾 requestAnimationFrame 不再执行。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:522)。
- **修复建议**：统一处理存储异常并保证循环调度不会因保存失败丢失；限制单段日志容量、提供导出/清理入口。此项是人为故障注入，不代表正常新档会立即触发。
- **证据用例**：C47, B28。

### F07 · P2 · 拆解后的立即保存与刷新代码被注释吞掉

- **复现**：背包内存在可拆解材料，点击拆解后立即比较内存状态与已保存的存档。
- **实际结果**：浏览器观测背包内存剩1件、存档仍有2件；信用点已发放。普通界面刷新/周期自动保存稍后会弥补。
- **预期**：拆解是一笔完整事务，完成后立即更新存档和界面。
- **原因定位**：save(); renderPanels(); 写在 // 注释尾部，没有执行。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:918)。
- **修复建议**：把保存和渲染恢复成独立语句。正常刷新存在 beforeunload 保存，不应把此问题夸大成“每次刷新都会回滚”；主要风险是自动保存前进程被直接终止。
- **证据用例**：C27, B13。

### F08 · P2 · 重塑结算依赖跑入结束后才保存

- **复现**：保存含10个待结算碎片的旧循环，执行 applyPrestige(1)，立即读取持久化存档。
- **实际结果**：内存已进入新局，但存档中的 prestiges 仍为0。一般会在跑入结束或周期保存时补写。
- **预期**：确认重塑后应先持久化结算结果，再进行表现动画。
- **原因定位**：applyPrestige() 没有立即调用 save()，依赖 openingRunIn() 中延迟保存。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:976)。
- **修复建议**：在清零局内状态、结算奖励后立即保存，动画作为后续表现。此项通过真实函数测试确认旧档窗口；未进行操作系统强杀实测，普通刷新会触发 beforeunload 兜底。
- **证据用例**：C35。

### F09 · P3 · 受阻弹窗的重塑按钮未应用新版按钮样式

- **复现**：触发行动受阻，检查重塑按钮。
- **实际结果**：实际 DOM className 仅为 mag，新版 nh-button 和 nh-button--violet 丢失；图标与文字呈旧布局。
- **预期**：受阻重塑按钮使用新版紫色按钮组件。
- **原因定位**：同一个 button 上写了两次 class 属性，浏览器保留第一次。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:818)。
- **修复建议**：合并为一个 class 属性。截图：18-wall-confirmed.png。
- **证据用例**：B08。

### F10 · P3 · 属性技能弹窗将已通关楼层多写一层

- **复现**：击败第10层 Boss，等待属性技能三选一。
- **实际结果**：bestEver=10、当前楼层已推进为11，弹窗却写“突破第11层”。
- **预期**：提示“突破第10层”，或使用不含已完成楼层的文案。
- **原因定位**：onKill() 先 S.floor++，offerSkills() 再直接使用 S.floor。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:934)。
- **修复建议**：把刚完成的楼层显式传入技能弹窗，避免仅依赖随时变化的全局楼层。截图：19-skill-floor-off-by-one.png。
- **证据用例**：B31。

### F11 · P3 · 版本与交接记录落后于实际代码

- **复现**：对比页面标题、顶部标签、封面版本和变更记录。
- **实际结果**：实际 VERSION 为v2.28.8；顶部写V2.24，浏览器标题仍为数值原型v0.1；CHANGELOG到v2.28.6，交接文档停在v2.24阶段。
- **预期**：测试者可以可靠识别当前版本及版本差异。
- **原因定位**：版本文字分散硬编码，记录更新不完整。 [源码位置](/Users/zmy/WorkBuddy/CrazyGames/game/index.html:377)。
- **修复建议**：统一由 VERSION 生成可见版本文案，并补齐文档。v2.28.8历史快照存在且与游戏本体一致。
- **证据用例**：静态检查。

## 性能与下载的验收限制

浏览器短采样180帧平均间隔约66ms；复核120帧平均约61.3ms、中位66.2ms、P95约82.6ms。空白对照页90帧平均约25.9ms，同样未达稳定60FPS。7.39秒采样中，ScriptDuration约0.086秒、LayoutDuration约0.0675秒、RecalcStyleDuration约0.0564秒、TaskDuration约0.383秒。

这些数据说明当前测试环境下视觉帧率偏低，值得进一步检查，但不足以将原因归结为 JavaScript 阻塞，也不能外推为手机实际帧率。**性能不标记通过**；建议在真实 Chrome/Safari 前台固定设备上补测帧率、GPU合成、发热与连续运行。
