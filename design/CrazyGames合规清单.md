# CrazyGames 平台规则分析与合规清单

> 来源：docs.crazygames.com 官方文档（2026-09-11 核实） · 适用项目：《霓虹猎手》
> 结论先行：**我们的设计方向基本合规，但发布策略要改（两阶段发布），广告点位 UI 有 2 处不合规需修，英文本地化是硬性缺口。**

---

## 1. 最重要的发现：两阶段发布（改变路线图）

| 阶段 | 要求 | 变现 |
|---|---|---|
| **Basic Launch（基础发布）** | 上传即审，**SDK 可选**，无强制集成 | ❌ 关闭 |
| **Full Launch（完整发布）** | 被平台邀请后才能进，**必须完整接入 SDK** | ✅ 开启广告分成 |

- Basic Launch 是约 **2 周的软启动窗口**：平台观察真实数据（平均时长、游玩转化率、留存），达标才被邀请进 Full Launch
- **对我们的意义**：不用等 SDK 接完才提交！美术完成后就可以先提 Basic Launch 攒数据，SDK 留到被邀请后再接
- QA 反馈通常 **1~2 天**（不是之前预估的 1~2 周），已上线游戏的更新当天处理
- 开发者门户自带 **QA Tool**：提交前可以模拟 CrazyGames 环境自测，务必先用

## 2. 技术规则 → 我们的状态

| 规则 | 要求 | 霓虹猎手状态 |
|---|---|---|
| 初始下载 | ≤ 50MB（移动首页需 ≤ 20MB） | ✅ 单文件 < 100KB，碾压级达标 |
| 总文件 | ≤ 250MB / ≤ 1500 个 | ✅ |
| 进入可玩 | ≤ 20 秒，Full 版要求**落地即玩**（最多 1 次点击） | ✅ 打开即玩，无菜单 |
| 路径 | 只能用相对路径 | ✅ 单文件无外部依赖 |
| 刷新率 | 物理表现在 144Hz/165Hz 一致 | ✅ 已用 dt 增量驱动 |
| 浏览器 | Chrome/Edge 必须正常；Safari 不行会被禁用该端 | ⚠️ 需实测 Safari |
| Chromebook | 4GB 内存设备要流畅 | ✅ 轻量 DOM 渲染 |
| 移动端 | body 加 `user-select:none`；防双击放大 | ✅ 已有 / v0.6 补 touch-action |
| 横屏 | 桌面横屏可玩 | ✅ 布局即横屏 |
| 全屏 | 平台自动提供，**禁止游戏内自做全屏按钮** | ✅ 没有 |
| 音频 | iOS 切后台后需在用户手势里 resume AudioContext；广告时必须静音 | ⬜ 阶段 4 加音频时处理 |

## 3. 玩法/内容规则 → 我们的状态

| 规则 | 要求 | 状态 |
|---|---|---|
| **语言** | **必须有英文本地化**；建议按 SDK locale 自动切换，回退英文 | ❌ **当前全中文——硬性缺口** |
| 适龄 | PEGI 12（13+） | ✅ 卡通战斗无血腥 |
| 文字可读 | 在 907×510 等 iframe 尺寸、devicePixelRatio=1 下可读 | ⚠️ 需在 QA Tool 实测 |
| 导流 | 禁止交叉推广/App Store 链接 | ✅ 无外链 |
| 原创性 | 名称、素材需原创 | ⚠️ AI 生成素材需注意版权干净 |

## 4. 广告规则 → 我们点位的修订（重点！）

只允许 SDK 广告。三类：Midgame（关卡间插屏）、Rewarded（激励视频）、Banner。

### 4.1 通用硬规则
- 广告**不得打断进行中的游戏**；不得惊吓式触发；**不得连播**
- 广告期间**游戏必须暂停 + 屏蔽输入**（发起到 adFinished/adError 全程 block UI）
- 广告开始播放时才静音，结束后恢复
- `adError`（无广告填充/AdBlock）时**游戏必须正常继续**
- **AdBlock 用户不得被封禁或惩罚**；激励广告按钮不能"点了没反应"——要么隐藏要么明示

### 4.2 激励视频（我们 3 个点位全是这类）细则
- 不得过于频繁，按钮要有**计时器**提示冷却
- **"不看广告直接拿基础奖励"的按钮必须和看广告按钮同样式**（同大小/字体/颜色）——⚠️ 我们目前是金色高亮 vs 灰色普通，**不合规，接 SDK 时改成同样式**
- 必须一眼看出"看广告换奖励"（加视频图标）
- 必须提供**非广告替代途径**（如用金币购买同等奖励）——⚠️ 我们的 ×2 没有金币替代，**需补**
- 离线收益 ×2、过关翻倍是官方推荐的经典点位 ✅
- Midgame 频率平台自动控制（≤1 次/3 分钟），可以在任意合适时机请求

### 4.3 我们广告点位的合规修订方案

| 点位 | 现状 | 修订 |
|---|---|---|
| 离线收益 ×2 | ✅ 官方推荐模式 | 补"跳过"按钮同样式 |
| 补给箱（1小时冷却） | ✅ 有计时器 | 补金币购买替代 + 同样式跳过 |
| 碎片 ×2（重塑结算） | ✅ 高价值时刻 | 补同样式跳过按钮 |
| **新增：Midgame** | 无 | 卡关/重塑后的楼层过渡处可请求，平台自动控频 |

## 5. 变现与付款规则

- 收入 = SDK 广告分成（具体比例官方未公开；2026 游戏 jam 条款参考值：广告 60% / 内购 70% 归开发者）
- **提现门槛 €100**，次月 10 日前经 Tipalti 月付（电汇/ACH/PayPal）
- 美英澳等 Tier 1 英语市场收益最高——**英文本地化不只是合规，是收入关键**
- 累计 5 万游玩后，官方提供一对一 SDK/广告位技术支持
- 分析工具：官方推荐 ByteBrew（免费）做漏斗和流失点分析
- 内购（Xsolla）为邀请制，MVP 不考虑

## 6. 修订后的发布路线图

| 阶段 | 内容 | 变化 |
|---|---|---|
| 1~3 | 策划/原型/调数值 | 不变 |
| 4 | 美术 + **英文版**（i18n，locale 自动切换） | 新增英文硬需求 |
| 5a | **Basic Launch 提交**：QA Tool 自测 → 上传（可不带 SDK）→ 2 周软启动攒数据 | 策略变化：提前提交 |
| 5b | 被邀请后接 SDK 完整版（广告合规修订 + 云存档 + 账户）→ Full Launch 开启变现 | SDK 后置 |
