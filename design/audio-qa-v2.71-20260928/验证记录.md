## 浏览器实测

在实际`game/index.html`上运行[可复现脚本](browser-audio-qa.cjs)，分别使用Chromium与WebKit内核的桌面、390px移动视口。两轮均得到以下结果：[Chromium原始结果](browser-results-chromium.json)、[WebKit原始结果](browser-results-webkit.json)。

| 场景 | 结果 |
|---|---|
| 首次进入 | 65/65音频解码，AudioContext为running；无音频加载警告、无页面错误 |
| 8×改装演出 | A01按现实时间运行，不随战斗倍速加速 |
| 后台与恢复 | 模拟`document.hidden`/`visibilitychange`后演出时钟冻结且音轨停止；恢复从冻结位置重建声源 |
| 刷新读档 | 改装轨从已保存的约1秒偏移续播，未回到0秒 |
| 移动端普通敌人入场 | 真正跑入落位后C09护盾展开成功播放1次 |
| 移动端Boss入场 | E12成功播放1次，同次未叠加C09 |
| 并发压力 | 10个不同声部请求中只启动8个，符合上限；清理后活动声部归零 |
| 390px画面 | 无水平溢出，改装面板宽366px；[Chromium游戏](mobile-game-chromium.png)、[WebKit游戏](mobile-game-webkit.png)、[Chromium改装](mobile-upgrade-chromium.png)、[WebKit改装](mobile-upgrade-webkit.png)截图人工检查无明显遮挡 |

测试中的后台状态由脚本模拟浏览器可见性事件；移动视口为桌面浏览器仿真，并非实体手机。为迅速到达Boss和改装状态，脚本构造了测试存档状态；截图中的楼层与Boss组合不能作为自然流程截图。真人耳机、扬声器听感，以及iOS设备上的真实Safari仍未验证。

## 素材响度核对

[逐项PCM测量](asset-levels.json)显示，本批13项单文件峰值范围为-17至-10dBFS；A01/A04均为精确8秒，峰值-16dBFS。C07护盾吸收比C08破盾轻，流程提示与战斗告警的素材峰值也留有余量。这里仅为文件级峰值与全文件RMS，**不能推出游戏最终混音或人的听感已经合格**。本轮未见需要立即修复的削波、缺文件或播放失控证据，因此没有仅凭测量调整增益。

## 真人试听入口与剩余工作

[打开13项试听清单](试听清单.html)可以逐项播放原始WAV；已验证页面列出13项且首项可正常解码。应在游戏内再检查事件时机、音量、叠音和A01/A04与F05的衔接，因为独立试听不含运行混音。若主观听感反馈指出具体音效，按事件定点调整并另起版本、快照与回归记录。已知核心C75仍是75/76中的唯一失败，本次未修。CrazyGames SDK与平台验证仍是上线前独立事项。
