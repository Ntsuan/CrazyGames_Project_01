# 霓虹猎手：手机按钮与倍速问题修复方案

基线版本：v2.34.1  
日期：2026-09-20  
状态：问题定位与修复设计；尚未修改游戏源码  
适用工程：`/Users/zmy/WorkBuddy/CrazyGames`

## 1. 结论与修复目标

当前存在两项相关问题：

| 编号 | 问题 | 已定位原因 | 修复目标 |
|---|---|---|---|
| INPUT-01 | 手机点按间歇失效，可能影响后续按钮 | 按钮或内部触摸目标被周期性重建，触摸结束处理及状态清理可能丢失 | 有效点按只执行一次；滑动和取消不执行；旧手势不影响新操作 |
| SPEED-01 | 2× 与 1× 的画面节奏差异很弱 | 战斗结算加速，但动画、死亡等待、换怪和转场仍使用固定真实时长 | 已通关楼层的战斗及演出同步加速，途中切速保持一致 |

两者的关联是：面板刷新使用倍速后的时间，2× 下重建更频繁；主要战斗演出却没有同步加快。因此玩家既感受不到明显加速，又更容易遇到按钮漏点。

实施顺序：先修复稳定节点与触摸状态，再统一倍速时序，最后进行真机联合回归。

## 2. 已有证据与判断边界

### 2.1 手机按钮

用户录屏时长约 18.39 秒，画面版本为 v2.34.1。主要操作包括攻击、生命升级及装备合成，多数时间开启 2×。录屏中有成功升级、合成完成的反馈，说明并非业务永久锁死。

录屏没有触点轨迹或浏览器事件日志，不能从等级短时间未变化推断失败点击次数，也不能确认每一次真机漏点都来自同一原因。录屏未展示技能三选一操作。

隔离浏览器使用实际游戏代码、真实主循环与合成 TouchEvent，补充验证结果如下：

| 场景 | 结果 |
|---|---|
| 从攻击或生命 button 自身起触，跨刷新后移动 9px 松手 | 升级成功，触摸状态清理 |
| 从攻击或生命内部文字起触，跨刷新后移动 9px 松手 | 原文字节点脱离文档，未升级，tapBtn 残留 |
| 从合成按钮起触，跨刷新后移动 9px 松手 | 原按钮脱离文档，未合成，tapBtn 残留 |
| 100ms 短点跨过下一次刷新，位移 9px | 同样复现文字节点失效、未升级和状态残留 |
| 节点保持稳定，9px / 10px 点按 | 触发业务 |
| 11px touchmove 后松手 | 不主动触发业务 |
| 没有中间 touchmove，仅松手坐标变化 11px | 仍触发业务，说明缺少松手复核 |
| 11px 滑动取消后另行派发 click | 仍执行业务，说明 click 路径缺少取消守卫 |

100ms 场景通过设置测试夹具 `saveTimer=.49`，使下一次刷新落在按住期间；它证明短点也可能受影响，不是对真人漏点比例的统计。合成事件不能替代手机原生滚动仲裁、兼容 click 和目标移除后行为的验证。

### 2.2 倍速

在 390×844 浏览器视口、相同基础属性和已通关楼层上对比。攻击次数测试将敌人生命设为足够高、攻击设为 0，以排除击杀与死亡干扰，保留实际攻击函数。

| 项目 | 1× | 2× |
|---|---:|---:|
| 约 4 秒内攻击次数 | 5 次 | 10 次 |
| 单次射击 CSS 动画 | 0.32 秒 | 0.32 秒 |
| 待机 CSS 动画 | 1 秒 | 1 秒 |
| 手机跑入配置 | 360ms | 360ms |
| 普通怪死亡至下一只就绪 | 2077ms | 2083ms |

战斗结算的倍速已生效，换怪耗时基本没有变化。录屏中经常一击击杀，固定等待占据主要时间，因此整体节奏差异很弱。

现有规则“仅已通关楼层允许加速”正常：`bestEver=10`、进入第 11 层时，有效速度恢复为 1，倍速按钮隐藏。

## 3. INPUT-01：修复手机按钮失效

### 3.1 原因与代码位置

以下行号对应 v2.34.1，后续修改以函数名和逻辑为准。

| 位置（game/index.html） | 当前行为 | 影响 |
|---|---|---|
| 1107、1109：renderPanels | 重写攻击、生命按钮 innerHTML | 外层 button 保留，内部 span、img 被替换 |
| 1113：renderPanels | 重写 gearBox.innerHTML | 合成、拆解按钮本身被替换 |
| 1146：renderPanels | 重写 treeBox.innerHTML | 加成树按钮也存在同类风险，需要回归 |
| 1242：loop | 倍速后的时间每超过 0.5 秒刷新面板 | 1× 约 500ms，2× 约 250ms；暂停战斗仍刷新 |
| 1555–1572：统一触摸监听 | document 委托，tapBtn 保留起始按钮 | 目标失效后可能漏掉结束事件；旧引用可能污染后续操作 |

技能选择按钮使用同一 `.nh-button` 触摸逻辑，并非漏绑；其节点不被 renderPanels 定时重建，但仍受统一触摸逻辑缺口及旧状态残留影响。

### 3.2 稳定按钮及内部节点

1. 攻击、生命按钮的图标、标题、数值、费用结构只初始化一次。属性变化时更新现有叶子节点，不替换整个按钮内容。
2. 装备按部位保留稳定容器。合成、拆解按钮长期保留，按当前材料状态更新内容、显示与禁用状态；避免每次刷新重建整块装备面板。
3. 加成树采用相同策略。列表确需增删时，按稳定标识更新，避免无差别替换全部节点。
4. 数据未变化时跳过更新。单纯缓存整段 HTML 只能减少替换，不能解决数值恰好在按住期间变化的情况。
5. 将界面刷新从倍速后的战斗 dt 中移出，使用真实时间和必要的状态变化触发。降低刷新频率不能替代节点稳定性修复。

### 3.3 完整处理一次触摸

建议保留一条统一输入入口，避免新增一套 Pointer Events 后与原 touch/click 同时触发业务。是否迁移输入 API 可另行决定，本次修复不以迁移为前提。

一次手势至少记录：发起手指标识、稳定按钮引用、起点、是否曾超阈值、是否取消、是否已经执行。

- 开始：仅接收有效、可操作的目标；其他手指不覆盖当前手势。
- 移动：建议按 CSS px 的直线距离判断 `Math.hypot(dx, dy) > 10`。中途超阈值即取消，移回起点也不恢复。
- 松手：再次计算最终位移；确认是发起手指，目标仍连接、仍可操作、未取消且未执行，才允许触发一次。
- 清理：无论执行或取消，都清除按压样式、按钮引用和手指标识。页面失焦、进入后台、弹窗替换、目标失效时也必须清理。
- click：区分正常鼠标/键盘激活与触摸产生的后续兼容点击。对已取消手势拦截其关联 click，对已主动执行的触摸避免重复执行；不要用全局长时间禁止 click 的方式误伤下一次正常点按。
- 执行：合成材料、升级费用、技能候选是否有效，仍由业务函数在执行时复核。

原实现按横纵两轴分别判断 10px；改为直线距离是本方案建议的规则调整，需同步更新测试预期。恰好 10px 允许，超过 10px 取消。这里是移动容差，不是时间防连点。

## 4. SPEED-01：修复倍速与演出不一致

### 4.1 原因与代码位置

| 位置（game/index.html） | 当前行为 |
|---|---|
| 1206：loop | dt 乘以 effSpeed，战斗结算已加速 |
| 55 起：角色 CSS | 射击、跑步、死亡等动画为固定秒数 |
| 688、1063：enemyAnim / lunge | 动作恢复回调使用固定 setTimeout |
| 736–738：onKill | 普通怪死亡后固定等 1650ms 才开始下一只跑入 |
| 745–763：runCfg / enemyRunIn | 手机跑入 360ms，刷怪回调再加 50ms |
| 798–833：转场函数 | 跑出、换背景、跑入、恢复战斗采用固定时长 |
| 1293：effSpeed | 新楼层恢复常速，保留该规则 |

### 4.2 分清游戏时间与真实时间

| 类型 | 随有效倍速变化 | 处理原则 |
|---|---|---|
| 攻击、敌方伤害、战斗超时、Boss 相位 | 是 | 沿用统一游戏时间推进 |
| 击杀停留、死亡、换怪、跑入、跨层演出 | 是 | 动画和逻辑完成条件同步 |
| 战斗增益、无敌窗口 | 建议是 | 统一计时并验证相对收益，避免混用 Date.now 与游戏时间 |
| 输入、界面刷新、提示文案 | 否 | 使用真实时间，不因 2× 重建更频繁 |
| 存档时间戳、日志真实耗时、广告及外部交互 | 否 | 保持真实时间语义 |

当前部分增益使用 Date.now。将其纳入游戏时间会改变现有 2× 下的实际收益，属于修复计时一致性时需要验证的行为变化，应在变更记录中明确。

### 4.3 推荐实现方式

1. 引入集中管理的游戏时间和演出调度，剩余时长按有效倍速消耗；不要分散修改大量固定 setTimeout 常量。
2. 将换怪与跨层流程拆成明确阶段，阶段完成后进入下一阶段。继续保留 runSeq 等失效保护，复位、重塑后取消旧流程。
3. 动画进度与阶段剩余时间使用同一有效速度。途中由 1× 切 2× 或恢复 1×，从当前进度继续，不能重播、瞬移或保留旧完成回调。
4. 区分“暂停战斗”和“暂停整个演出”。当前转场会设置 paused=true，但跑入、换场仍应继续；不能简单让所有调度随 paused 一起停，否则流程会卡死。
5. 进入新楼层时统一更新有效速度。基于现有规则，切入未通关楼层即恢复常速；画面、阶段调度和按钮显示保持一致。
6. 将战斗相关 CSS 动画与调度同步。只缩短 CSS 时长会出现动作结束后等待逻辑，只缩短回调又可能截断动画，两者必须一起处理。

第一版保持 1× 原有时长不变，以降低回归范围；2× 将对应游戏过程的真实耗时缩短至约一半。

## 6. 验收矩阵

### 6.1 输入

覆盖攻击、生命、装备合成、拆解、加成树、技能三选一和倍速按钮。

| 场景 | 验收标准 |
|---|---|
| 文字、图标、空白处起触 | 均可正常点按，不因命中子节点而失效 |
| 1× / 2× 连续短点、按住跨刷新 | 每个有效手势恰好执行一次；节点与状态正常 |
| 0 / 9 / 10 / 11px；横向、纵向、斜向 | 按约定距离规则判定；松手坐标同样检查 |
| 滑动超过阈值后返回原位 | 保持取消，不执行 |
| 滚动、touchcancel、多指 | 不误触；其他手指不触发或清除主手势 |
| 合成后打开技能、弹窗替换、切后台再返回 | 旧手势不影响新按钮，无按压样式或引用残留 |
| 材料不足、费用不足、按钮失效 | 不执行业务，不遗留输入状态 |
| 鼠标、键盘 Enter / Space | 正常可用，无双重触发 |

真机至少覆盖用户录屏对应的 iPhone 环境，并记录实际浏览器及系统版本；若支持 Android，再补充 Android 浏览器。测试时记录事件类型、identifier、目标连接状态、手势取消原因和业务执行次数。诊断日志仅用于测试，避免每帧写入持久存储。

### 6.2 倍速与联合回归

| 场景 | 验收标准 |
|---|---|
| 相同配置持续战斗 | 2× 单位真实时间的攻击次数接近 1× 的两倍，允许计数边界误差 |
| 一击击杀、普通换怪、Boss 转场 | 对应演出实际耗时在 2× 下约减半 |
| 同一已通关楼层完整流程 | 排除手动技能选择和外部等待后，2× 总耗时接近 1× 的一半；建议受控测试允许约 ±10% 偏差 |
| 跑动、死亡、换背景中途切速 | 进度连续，动画与逻辑同时完成，无跳帧式重播或额外等待 |
| 进入未通关楼层 | 逻辑和演出同步恢复 1×，按钮状态符合既有规则 |
| 重塑、复位、刷新恢复、技能弹窗 | 无旧回调执行、卡住、重复奖励或错误解暂停 |
| 增益、无敌、Boss 蓄力 | 动画提示、效果持续与伤害时点一致；检查计时迁移后的数值表现 |
| 2× 下频繁操作按钮 | 演出加速不提高 UI 重建频率，不复发漏点或误触 |
