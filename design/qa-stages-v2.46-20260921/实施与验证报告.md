## 已接入的规则

- 基础攻击：8 / 12 / 16 / 24 / 32；基础生命：100 / 150 / 200 / 300 / 400。每个阶段使用绝对基础值，不继承毕业属性。
- 前四阶段击败 100 层 Boss 后先完成死亡、淡出，再显示改装确认；不去 101 层，不弹十层重塑／广告／技能。
- 点击确认后一次性保存新阶段第 1 层，清空信用点、已有／本轮碎片、装备背包、强化、技能、树、保底、箱数、阶段最高层及倍速资格。无装备回收启动金；补给就绪状态按新阶段初始化。
- 音效／倍速偏好、阶段历史与日志保留。倍速偏好保留不代表新阶段有倍速资格。
- 8 秒演出使用原四段美术，只有前台实际播放计时；不受 2× 影响。每约 0.5 秒保存进度，后台／关闭再补存。异常退出最多重播最近未保存的小段，不提前完成。
- 演出没有跳过、关闭或提前入场。完成写入失败提供“重试保存”；播放中断恢复演出，已完成恢复完成页。
- 第五阶段从第一层无尽，没有阶段 6；每十层可普通重塑，包括百层；普通重塑保留当前阶段、当前阶段树和已有碎片，仍沿用现行装备回收规则。
- HUD 显示阶段名称；1–4 阶段显示 /100，第五阶段显示 ∞ 无尽。旧“永久加成”文案改为“本阶段加成”，避免与跨阶段清空冲突。

## 存档迁移与失败处理

- 沿用 neonHunter 主键；阶段 schema 与历史装备 v 分开，防止重复品质迁移。
- 无阶段字段的合法旧档先原样备份到 neonHunter.preStages，再补阶段 1。旧档已超过 100 层或存在百层后待办，只标记迁移资格，不自动清空／连升。
- 先恢复旧重塑／技能选择。完成原选择后显示明确的旧档升级预览，原资源仍保留；确认后只升至阶段 2。
- 新阶段、资源清空、改装 id 与 playing 状态在一次 localStorage 写入中提交；失败不修改内存原局。complete 与入场同样先写再推进。
- 非法 JSON、非法阶段、未知阶段 schema 或矛盾改装数据不覆盖原存档。封面提供原始备份导出，玩家仍可通过设置明确清档新开。
- 一般浏览器存储清理／跨设备同步不在本次范围。升级后的存档不应直接交给 v2.45.2 继续游戏；回退需先导出完整新存档，并明确选择旧备份，不能自动丢弃新进度。
