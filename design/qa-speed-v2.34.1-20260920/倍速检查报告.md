# v2.34.1 倍速检查

结论：2× 已用于战斗 dt，但没有覆盖主要演出。战斗结算更快，画面不等比例加快；一击击杀时，固定换怪等待占据主要时间，体感差异很弱。

## 浏览器实测

在冻结副本、390×844 视口、相同基础属性和已通关楼层上比较，给测试敌人足够生命、将其攻击设为 0，排除死亡与转场干扰。保留实际攻击函数，仅包裹计数。结果：

| 项目 | 1× | 2× |
|---|---|---|
| 4 秒内攻击次数 | 5 | 10 |
| 单次射击 CSS 动画 | 0.32 秒 | 0.32 秒 |
| 待机 CSS 动画 | 1 秒 | 1 秒 |
| 手机跑入配置 | 360ms | 360ms |
| 小怪死亡至下只就绪 | 约 2.06 秒 | 约 2.06 秒 |

换怪实测精确读数见 results.json。未验证原生手机动画帧率，本结果是隔离浏览器代码与时序验证。

## 原因及位置

- `game/index.html:1206` 仅将主循环 dt 乘以 effSpeed()；攻击积累、敌人伤害、战斗超时与 Boss 相位按此推进。
- `:55` 起的 CSS 动画使用固定秒数，未接入倍速；`:1068` 等动作移除定时器也使用固定时长。
- `:736`–`:738` 普通击杀后等 1650ms 才开始新敌人跑入，`:745` 手机跑入配置 360ms，`:758` 回调另加 50ms，总计约 2060ms，两档相同。
- `:805`–`:831` 跨楼层跑出、场景切换、跑入、恢复战斗同样使用固定 CSS 时长与 setTimeout。
- `:1293` 倍速仅作用于已通关楼层，新楼层恢复 1×；`:1298` 对应按钮隐藏。实测 bestEver=10、floor=11 时有效速度=1，按钮隐藏，符合现有设计。
- 与前述触摸缺陷相关：面板刷新时间也使用倍速 dt，因此在视觉没有同步变快时，按钮内容重建却变频繁。

## 修复建议

1. 统一战斗时间推进，使攻击、增益与无敌时长、敌人死亡、换怪、跑入、转场按同一有效速度运行；现有部分增益使用 Date.now，改动时需一起审计，避免倍速改变增益的相对收益。
2. 战斗 CSS 动画/位移动画与对应 JS 完成回调同步缩放；在途中切换速度时同步调整剩余时长，避免只改 CSS 导致画面到位却仍在等待回调。
3. UI 刷新、触摸处理、按钮反馈、提示文案按真实时间运行；按钮采用稳定 DOM，避免倍速使输入问题恶化。
4. 按一击击杀与持续战斗两种场景，对比同一已通关楼层从开始到下一层的真实耗时；已知技能选择等待单独统计。验证 2× 总耗时接近 1× 的一半，并检查进入新楼层、途中切速时的动画与结算一致性。

未修改游戏源码；独立浏览器页面和服务已清理。
