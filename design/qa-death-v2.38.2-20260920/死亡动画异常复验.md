# v2.38.2 死亡动画异常复验

结论：已修正素材路径与末帧终点，但动画步数仍为 steps(8)，造成中间帧切片错位。浏览器已复现角色被切开、相邻帧同时露出的画面。

## 根因

`game/index.html:64` 实际仍为：

```css
animation: gunnerDeath calc(var(--spd,1)*.9s) steps(8) forwards;
```

关键帧终点为 -770px，背景显示尺寸为 880×110px。8 个角色帧各宽 110px，合法切片起点应为 0、-110、-220、-330、-440、-550、-660、-770px。

当前 770÷8=96.25px，每步都不是一帧的宽度。因此起点和终点虽然对齐，中间画面都在跨帧取样。例如播放到 450ms 时实际偏移 -385px，相当于 3.5 帧，显示窗口同时截取相邻两帧。

CHANGELOG 写了 steps(7)，但当前实际样式仍是 steps(8)，记录与实现不一致。以浏览器 computed style 和源码为准。

## 最小修正

保留当前正确的素材路径、880×110 背景尺寸和 -770px 终点，只将死亡动画的 steps(8) 改为 steps(7)：

```css
#player .psprite.death {
  background-image: url('assets/stage01-death.png');
  background-size: 880px 110px;
  background-position: 0 0;
  animation: gunnerDeath calc(var(--spd, 1) * .9s) steps(7) forwards;
}
@keyframes gunnerDeath {
  from { background-position-x: 0; }
  to   { background-position-x: -770px; }
}
```

这里有 8 个有效帧位置，所以需要 7 次位置跳变。不要把 steps(8) 单独保留，也不要把终点退回 -880px，否则将重新出现末帧空白。

如产品希望倒地姿势在弹窗出现前停留一段时间，需要另设明确停留时长；这属于节奏优化，不是本次切片错误的必要修复。

本次未修改游戏源码，仅在独立浏览器页面验证样式预览。修复落地后应复测 1×/2×、射击中死亡、末帧停留以及受阻弹窗时机，并同步版本、快照和 CHANGELOG。
