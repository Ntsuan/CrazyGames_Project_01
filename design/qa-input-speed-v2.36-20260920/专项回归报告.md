## F01｜P2：滑动取消后快速重新点按，正常点击被吞

位置：`game/index.html:1595`、`:1599`，触摸取消与 click 捕获守卫。

复现：

1. 攻击按钮按下，松手位置偏离起点 11px，取消该手势。
2. 在 100ms 后，再对同一按钮做一次有效点按。
3. 预期升级 1 次，实际等级仍为 0。

原因：取消时设置 `suppressClickFor=b`，保留 350ms；新有效手势没有清除或更新该守卫。新手势主动调用的 `b.click()` 被当成旧手势的尾随 click 拦截。

建议：用手势身份区分旧兼容 click 与新有效手势；主动派发的合法点击需要明确通行。避免只凭“相同按钮 + 时间窗口”拦截，也不要用全局禁止点击处理。补测滑动结束后立即、100ms、超过守卫窗口再次点按，以及鼠标/键盘激活。

证据：`input-results.json`、`edge-results.json`。

## F02｜P2：装备内容变化时，合成按钮仍被整体重建

位置：`game/index.html:1121`–`:1151`，gearSig 缓存和 gearBox.innerHTML；`:1574`–`:1604`，触摸状态清理。

复现：

1. 准备可合成材料，按住合成按钮标题。
2. 按住期间发生装备变化；已分别测试加入其他部位材料，以及调用实际 `dropRoll(true)` 触发必掉落。
3. 等待定时刷新后，在原目标上以 9px 位移松手。
4. 原目标 `isConnected=false`，未执行合成，`tapBtn` 仍残留。

原因：签名缓存解决了“内容不变也重建”，但只要装备变化，仍替换整个装备区域。触摸目标移除后，结束事件不再冒泡到 document；末尾的 `isConnected` 检查没有机会运行，也不能主动清理已丢失的手势。

建议：按装备部位保留稳定合成、拆解按钮及内部节点，增量更新；目标确需删除时主动取消相关手势。旧手势失效后必须清理，不能阻挡后续按钮。补测按住期间其他部位掉落、自动换装、材料变化与后续技能选择。

证据：`input-results.json`、`drop-results.json`。这是合成 TouchEvent 的复现，手机原生目标移除后的事件行为仍需设备日志确认。

## F03｜P2：加成树缓存使“资金已足够”仍显示不可购买

位置：`game/index.html:1161`，treeSig 将全部 `souls >= 10` 合并为一个签名。

业务路径复现：

1. 伤害树 Lv.13，下一次费用 14，现有碎片 10，按钮禁用。
2. 本循环有 4 枚碎片，调用实际重塑结算 `applyPrestige(1)`。
3. 结算后余额为 14，等待跑入和面板刷新完成。
4. 按钮仍为 disabled，仍显示“碎片不足”。

原因：重塑前后的树等级相同，10 和 14 都被缓存签名表示为 `>=10`，因此不更新可购买状态。不是触摸丢失，而是按钮保留了错误禁用状态。

建议：每次相关资源变化都更新各按钮的可购买状态和提示；若保留签名，至少纳入每项 `S.souls >= treeCost(k)` 的结果。更新状态时仍须保留稳定节点。

证据：`additional-results.json` 和下图。截图显示顶部余额 14，伤害树费用 14，但仍禁用。

## F04｜P2：倍速演出覆盖和动态同步尚不完整

### 跑出过程中突然跳位

位置：`game/index.html:807`–`:809`。

玩家跑出 transition 仍为固定 `left 1.2s linear`，但 2× 的淡出回调已提前到约 575ms。回调将 transition 改为 opacity 时，尚未完成的 left 过渡被中止并跳到终点。

实测 2×：第 562ms 左坐标约 167.2px；第 579ms 突然变为 320.8px，transition 从 left 改为 opacity，角色此时尚未淡出。即跑到一半跳到门口。

建议：跑出位移时长、淡出起点、淡出时长及后续切场回调使用同一速度规则。背景切换目前仍固定等待 480ms，也应检查画面与阶段完成时间的一致性。

### 天枢动画漏接倍速

位置：`game/index.html:148`–`:166`。

天枢 CSS 动画仍是固定时长。实测 charge 动画在 1×/2× 都为 0.5 秒，但 `enemyAnim('charge',500)` 的恢复回调在 2× 为 250ms，动画可能在未播放完成时被移除。

建议：将天枢待机、跑入、攻击、蓄力、死亡一并纳入倍速，并核对技能伤害与提示时点。

### 中途切速不更新已开始的移动

位置：`game/index.html:746`–`:766` 及各处预先计算延迟的 setTimeout。

实测以 1× 开始敌人跑入，100ms 后切到 2×：当前位移 transition 仍是 0.36 秒，而新 runCfg 已为 180ms；该次跑入完成仍约 436ms。当前实现只对新调度的动作计算倍速，未同步既有动作的剩余时长。

建议：统一管理演出阶段进度和剩余时间，途中切速时同步调整动画及完成回调。只改变 CSS 动画速度或只改变新建定时器，都无法保证在途流程一致。

证据：`timing-results.json`、`edge-results.json`。
